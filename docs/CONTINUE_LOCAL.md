# Продолжение работы над DocMind локально

Ветка: `feature/04-embeddings-search`.

## Состояние

Этап 3 завершён и проверен: worker, TXT/Markdown/PDF, фрагменты, lease,
повторы, восстановление после сбоя и безопасное удаление. Прошли `go vet`,
`go test -race`, 17 интеграционных тестов PostgreSQL, Docker Compose и HTTP smoke.

Этап 4 сохранён как незавершённая работа. Добавлены:

- `internal/llm`: интерфейс embeddings, детерминированный fake и OpenAI HTTP-адаптер;
- `internal/config/embeddings.go`: выбор провайдера;
- worker с последовательными batch-запросами embeddings;
- миграция `004_embeddings.up.sql`: `vector(1536)`, модель документа и поколение задания;
- запись векторов, переиндексация с защитой от старого worker, поиск по cosine distance;
- `internal/rag/search.go`: проверка запроса, набора документов и совместимости моделей;
- `cmd/search` и `cmd/reindex`: команды поиска и переиндексации;
- существующие worker integration-тесты адаптированы к embeddings.

**Этап 4 ещё не принят как готовый.** Полный прогон integration-тестов после
его изменений не завершён. Новые тесты fake/OpenAI, batch-обработки и поиска
ещё нужно написать. README пока описывает этап 3.

## Получение ветки

```powershell
git fetch origin
git switch --track origin/feature/04-embeddings-search
```

Если локальная ветка уже существует, переключитесь на неё без `--track`.
Не перезаписывайте незакоммиченные локальные изменения.

## Настройки этапа 4

По умолчанию используется fake, ключ не нужен. При необходимости добавьте
в локальный `.env` (он исключён из Git):

```dotenv
EMBEDDING_PROVIDER=fake
EMBEDDING_HTTP_TIMEOUT=10s
```

Для OpenAI: `EMBEDDING_PROVIDER=openai` и собственный `OPENAI_API_KEY`.
Модель фиксирована: `text-embedding-3-small`, размерность 1536.
Fake-модель: `fake-hash-v1`, также 1536; это лексический тестовый провайдер,
он не моделирует семантику или синонимы. Векторы разных моделей не смешиваются.
Реальные платные вызовы OpenAI в облаке не выполнялись.

## Что доделать

1. Запустить `gofmt`, `go vet ./...`, `go test -race -count=1 ./...` и PostgreSQL
   integration-тесты с `TEST_DATABASE_URL`. Без него integration-тесты пропускаются.
2. Проверить миграцию 004 на чистой БД и на данных этапа 3. Она повторно ставит
   прежние `ready`/`processing` документы в очередь, сохраняя исходники и фрагменты.
   Старые worker нужно остановить до миграции.
3. Добавить тесты fake и OpenAI: порядок ответов по index, batch, размерность,
   нулевые/нечисловые векторы, неверные ответы, таймауты, отмена, 429/5xx и
   безопасные ошибки без ключа и текста документов.
4. Проверить релевантность pgvector-поиска на фиксированном корпусе, фильтрацию
   `document_ids`, состояние документов, несовпадение моделей и конкурентный DELETE.
5. Проверить переиндексацию: без дублей, повторная постановка уже queued — no-op,
   старое поколение задания не может завершить новую попытку с тем же номером.
6. Добавить сборку и копирование `cmd/search`/`cmd/reindex` в Dockerfile, команды
   в Makefile, переменные в `.env.example`; обновить README на русском.
7. Проверить полный Docker/HTTP сценарий и зафиксировать завершение этапа 4.
   К этапу 5 переходить только после проверки этапа 4 пользователем.

Сейчас новые CLI можно запускать через `go run ./cmd/search -documents UUID
-question "текст запроса" -top-k 5` и `go run ./cmd/reindex -document UUID`
после настройки env и применения миграций. В текущие Docker-образы эти CLI
ещё не добавлены. Публичного HTTP endpoint поиска пока нет; вопросы с ответами
и источниками относятся к этапу 5.
